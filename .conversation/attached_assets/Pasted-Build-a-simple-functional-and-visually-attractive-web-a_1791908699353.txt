Build a simple, functional, and visually attractive web application called
"DocuMind AI — Smart Document Q&A Assistant".

PROJECT GOAL:
Create a RAG (Retrieval-Augmented Generation) based document assistant
that allows users to upload PDF documents, ask questions about their
contents, receive answers grounded in the documents, and summarize them.

Keep the project beginner-friendly, easy to understand, and easy to
explain during a software engineering interview.

TECHNOLOGY STACK:
- Python for backend logic
- Streamlit for the frontend
- PyPDF for extracting text from PDF documents
- Sentence Transformers for generating text embeddings
- NumPy or scikit-learn for semantic similarity search
- Google Gemini API for generating answers and summaries
- Python session state for maintaining conversation history

IMPORTANT:
Build a working application, not just a frontend mockup.
Keep the code modular, clean, and well-commented.
Avoid unnecessary complexity, paid databases, and complicated
infrastructure.

CORE FEATURES:

1. PDF UPLOAD
- Allow users to upload one or more PDF documents.
- Display the uploaded filename, file size, and number of pages.
- Show a success message when a document is processed.
- Provide a button to remove or replace uploaded documents.
- Handle invalid PDFs and empty documents gracefully.

2. DOCUMENT PROCESSING
Implement a basic RAG pipeline:

Step 1: Extract text from PDFs using PyPDF.
Step 2: Split extracted text into chunks of approximately 500
        characters with a small overlap.
Step 3: Generate embeddings using Sentence Transformers.
Step 4: Store the embeddings in memory.
Step 5: Convert the user's question into an embedding.
Step 6: Retrieve the top 3 most relevant text chunks using
        cosine similarity.
Step 7: Send the retrieved context and user question to Google
        Gemini to generate a grounded answer.

Keep this pipeline simple and easy to follow.

3. ASK QUESTIONS
- Provide a chat interface where users can ask questions about
  their uploaded documents.
- Display user questions and AI responses as separate chat bubbles.
- Use the uploaded documents as the primary source of information.
- Display a friendly message when the answer cannot be found
  in the available document context.
- Show source document names and page numbers for retrieved
  information whenever possible.
- Support follow-up questions while the same documents remain loaded.
- Include a loading indicator while generating answers.

4. DOCUMENT SUMMARIZATION
- Add a "Summarize Document" button.
- Generate a concise summary of the uploaded document using Gemini.
- Display the summary in a readable card with headings and bullet points.
- For large documents, summarize text in manageable sections instead
  of sending the entire document in one API request.

6. GEMINI API CONFIGURATION
- Read the Gemini API key from an environment variable named
  GEMINI_API_KEY.
- Never hardcode or display the API key.
- Add clear setup instructions for configuring the secret in Replit.
- If the key is missing, display a helpful setup message.
- Do not silently generate fake AI answers when the API is unavailable.

7. PERFORMANCE AND RELIABILITY
- Cache the embedding model where appropriate.
- Avoid recomputing embeddings unnecessarily.
- Store document text, page numbers, chunks, and embeddings together.
- Keep processed documents in Streamlit session state.
- Clear cached document data when the user replaces documents.
- Handle large PDFs without crashing.
- Show helpful error messages instead of raw stack traces.
- Use appropriate API request limits and error handling.

Installation, setup, project overview, features, and instructions
for running the application.
